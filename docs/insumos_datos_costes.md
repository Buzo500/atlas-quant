# Datos y costes para Atlas: selección inicial

Verificación de fuentes primarias: **5 de septiembre de 2026**. Alcance: software personal local, acciones y ETF, valoración en EUR, investigación diaria y futura conexión con broker. Los precios son publicados, no presupuestos contratados; faltan impuestos aplicables, cambio de divisa y condiciones de cuenta. No se ha abierto ninguna cuenta ni adquirido servicio alguno.

La ruta viable empieza con importaciones del broker, una cesta limitada de instrumentos, fuentes públicas para investigación y documentos del emisor. El primer gasto justificable suele ser una cotización adecuada para la operativa; después, históricos más completos. Un catálogo de precios aparentemente amplio no demuestra que incluya empresas desaparecidas, documentos disponibles en cada fecha o datos aptos para ejecutar órdenes.

## Qué significa una base gratuita aceptable

Como decisión de diseño, limitaría el universo inicial a **10–30 instrumentos** y una actualización diaria. Esto es un límite de trabajo propuesto, no un límite común garantizado por las fuentes. Cargar 30 instrumentos exige al menos dos días con una cuota de 25 si cada consulta consume una solicitud y no hay otras peticiones. Una caché evita descargar de nuevo años de datos; una cola controla cuotas, errores y reintentos. La aplicación debe indicar fecha, proveedor y calidad de la última actualización, incluso si los datos están incompletos.

Los extractos son el punto de partida para reconstruir lo que realmente ocurrió en la cuenta. Para pruebas de código se necesitan además fixtures sintéticos: splits, dividendos, conversión de divisa, comisiones y deslistados con resultados conocidos. Un histórico gratuito puede permitir análisis descriptivo de los instrumentos elegidos; por sí solo no justifica afirmar que una selección de acciones habría funcionado en todo el mercado hace diez años.

Al comprar datos, empezaría con un mes y una prueba de aceptación de **20 instrumentos**: diez acciones USA, cinco europeas y cinco ETF UCITS de las bolsas de interés. Revisaría identidad, precios sin ajustar, ajuste por dividendo/split, calendario, divisa y al menos dos eventos corporativos conocidos. Este es un protocolo propuesto, no una certificación del proveedor. Un fallo no se oculta sustituyendo silenciosamente la serie: queda registrado y puede bloquear el cálculo afectado.

## Cotizaciones para órdenes y presupuesto incremental

IBKR publica snapshots USA a **USD 0,01**, otros instrumentos a **USD 0,03**, con exención mensual de **USD 1**. Tarifas mensuales no profesionales de referencia: Euronext L1 **EUR 3**, Borsa Italiana L1 **EUR 4**, Madrid Plus L1 **EUR 7**, Frankfurt/Xetra L1 **EUR 16,25**. Existe un paquete Deutsche Boerse ETFs sin cuota; hay que validar su alcance y permisos. Requisitos de saldo, usuario, cuenta y mercado siguen aplicando. [Tabla oficial](https://www.interactivebrokers.com/en/pricing/market-data-pricing.php).

La propuesta concreta es solicitar bid, ask, tamaños, timestamp y origen justo antes de preparar la orden. Si falta precio fresco o no coincide el contrato, la aplicación deshabilita envío. La antigüedad máxima será una política explícita comprobada en paper; por ejemplo, cinco segundos para una primera implementación asistida en sesión normal, no una garantía de ejecución. Una cotización no consolidada no debe etiquetarse como mejor precio del mercado. El dato diario sigue siendo adecuado para señales diarias; la pantalla de confirmación necesita otra calidad de información.

El software puede comenzar con **EUR 0/mes de suscripciones de infraestructura**, usando el equipo existente: excluye electricidad, conexión, almacenamiento de respaldo y trabajo. Pagar datos no exige alojarlo en la nube. El presupuesto inicial de datos puede quedarse en cero para investigación; para órdenes se elegirá el paquete o snapshots que cubran el instrumento. Comprar un histórico EOD tiene más sentido que añadir intradía antes de necesitarlo. Norgate se justificaría después, si el objetivo concreto es selección sistemática de acciones USA y el sesgo de supervivencia limita el estudio.

## Contratos de datos que debe imponer el diseño

Cada observación necesita `instrument_id`, mercado/MIC, divisa, hora del mercado, `effective_at`, `available_at`, `ingested_at`, proveedor y versión. En fundamentales debe distinguirse cierre contable de publicación; si esta última falta, el backtest no puede asumir disponibilidad inmediata. Los tickers son alias con fechas de vigencia. Separar instrumento, clase y cotización evita mezclar dos ETF parecidos o tratar una cotización en EUR como cobertura de divisa.

Guardar precios originales y ajustados, método de ajuste y eventos corporativos explícitos. Un dividendo no se suma de nuevo a una rentabilidad calculada desde una serie de retorno total. Para una fusión, escisión o exclusión, el ledger necesita el evento real y su tratamiento económico. Los constituyentes de hoy no reemplazan un universo histórico; conservar snapshots desde ahora solo resuelve el futuro, no reconstruye el pasado.

Norgate reconoce correcciones de su base sin notificación ni versionado; por tanto, incluso con proveedor pagado hacen falta snapshots locales reproducibles. Su FAQ tampoco ofrece directamente delisting returns ni historial exacto de bolsa. Estas carencias deben constar en los experimentos que las necesiten. [Limitaciones oficiales](https://norgatedata.com/data-package-faq.php).

Finalmente, registrar permisos por proveedor: uso personal, almacenamiento, redistribución, visualización y uso de API cuando proceda. Una demostración pública debe usar datos sintéticos o material con permiso de redistribución. Que la biblioteca sea abierta no vuelve abiertos los precios. Si algún día Atlas se convierte en producto para terceros, sus licencias de datos son una decisión nueva; no se heredan de este diseño personal.
