# D8 · Integración y entrega de desarrollo v0.4

10/09/2026. `0.4.0-dev.6`, esquema 5. El usuario autoriza D7, D8 y definir v0.5 como parte de las diez tareas. Este documento registra la integración y publicación; CI, fusión, etiqueta y operación definitivas también se anotan en continuidad. No equivale a versión estable ni reactiva el ensayo sostenido.

## Resultado

D1–D8 conectan identidad, datos versionados, libro independiente, conciliación, dividendos/splits, EUR/USD, valoración y rentabilidad por fechas. Se conservan políticas y resultados anteriores. Las nuevas rutas de D7 se consultan explícitamente y no añaden históricos al estado rutinario del motor.

El cálculo diario reutiliza el mismo reductor exacto del libro; avanza por movimientos ordenados en lugar de reconstruir todos los prefijos repetidamente. Los snapshots anteriores contienen valores independientes. No hay un segundo motor, escritor, microservicio o modelo de riesgo de ejecución nuevo.

NAV e informes comparten un máximo de dos cálculos pesados simultáneos por proceso. Un tercero recibe 503 explicado; los controles siguen disponibles. El cupo se libera también al fallar. Lectura SQLite coherente, cálculo fuera de transacción escritora, comprobación de revisiones y guardado/auditoría atómicos. Conflictos no provocan confirmación o reintento automático.

D7 guarda informe y resumen inmutables en el almacén de registros existente, sin alterar esquema ni libros. Fechas, política, contexto, fuentes, cortes diarios, flujos/costes y diagnóstico XIRR quedan registrados. Solo el indicador de vigencia se calcula al consultar; cifras históricas no se reescriben.

## Carga y recuperación ampliadas

`tools/benchmarks/benchmark_d8_delivery.py` crea una base nueva con 10 cotizaciones, 100.000 barras, 10.000 observaciones FX y 10.000 movimientos. Añade una demo legacy y diez experimentos en cola exclusivamente para comprobar controles, proveedor `none`, presupuesto cero y worker apagado. Windows nativo, Python 3.14.4, este sobremesa.

- Cinco NAV con serialización tras calentamiento: máximo **0,724 s**, pico de asignaciones Python medido con tracemalloc **142,62 MiB**.
- Cinco informes del límite de **3.660 días** con serialización: máximo **1,486 s**, pico Python **148,15 MiB**. P&L −32,85 EUR y costes 32,85 EUR, sin flujos; TWR contrastado contra 89910,099 / 89942,949 − 1 (patrimonio exacto antes del redondeo visual).
- Veinte controles HTTP sobre ASGI durante los informes, diez paradas y diez pausas: **p95 0,3721 s**, máximo 0,3905 s. Esta frontera incluye API/serialización, **no el transporte Node ni el navegador**.
- Copia, restauración y consulta de NAV e informe: resultados exactos; no se toca la base habitual. Evidencia `var/validation/d8-delivery-1827e2e35e824ab6ac83a01ab5a44b90/report.json`.

Se cumplen los presupuestos medidos de 5 s, 256 MiB Python y p95 1 s. El primer oráculo del benchmark comparaba TWR contra importes mostrados a céntimos; se corrigió para usar el patrimonio exacto declarado. No se alteró el motor para ajustar esa referencia.

Corrección D7: el refresco global de auditoría remontaba ambos paneles con claves además duplicadas; desaparecían fechas y previsualización. Regresión reproduce primero el reinicio incorrecto de fecha; después verifica fecha/token conservados, descarte al cambiar revisión, rechazo sin reintento y patrimonio conservado. La conexión de D3 sigue como incidencia de transporte sin causa acreditada; no se oculta con reintentos o mayores tiempos.

Validación local posterior: **278 frontend**, tipos/lint/build correctos y **19/19 E2E en 1,2 min**, `e2e-08ce8cbf7a7244b08809830f5119639f`, con sondas optativas.
